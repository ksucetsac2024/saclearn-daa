1. Master Theorem Quick Lookup

For recurrences of the form T(n) = aT(n/b) + f(n) where a ≥ 1, b > 1, compare f(n) with nlogb a:

Case Condition Polynomial Gap Solution T(n) Classic Example
Case 1 f(n) = O(nlogb a − ε) f(n) grows strictly slower Θ(nlogb a) T(n) = 8T(n/2) + n² ⇒ Θ(n³)
Case 2 f(n) = Θ(nlogb a logk n) Same growth rate (k ≥ 0) Θ(nlogb a logk+1 n) Merge sort: 2T(n/2) + n ⇒ Θ(n log n)
Case 3 f(n) = Ω(nlogb a + ε) f(n) grows strictly faster (requires a·f(n/b) ≤ c·f(n)) Θ(f(n)) T(n) = 2T(n/2) + n² ⇒ Θ(n²)
Master Theorem Inapplicability Trap

Master theorem fails when: (1) a is not constant (e.g. 2n T(n/2)), (2) b ≤ 1, (3) f(n) is not a polynomial difference (e.g. T(n) = 2T(n/2) + n/log n), or (4) regularity condition fails in Case 3.

3. Dynamic Programming Transition Formulas

0/1 Knapsack

K[i, w] =
  if w < wt[i]: K[i - 1, w]
  else: max(K[i - 1, w],
            val[i] + K[i - 1, w - wt[i]])

Matrix Chain Multiplication

m[i, j] =
  if i == j: 0
  else: min { m[i, k] + m[k + 1, j]
              + p[i-1]*p[k]*p[j] }
        for i <= k < j

Floyd-Warshall All-Pairs

D[k][i][j] =
  min(D[k-1][i][j],
      D[k-1][i][k] + D[k-1][k][j])

4. Complexity Classes & Reduction Chains

Definitions for KTU PCCST502 Part A
  • P: Decision problems solvable in polynomial time O(nk) by a deterministic Turing machine.
  • NP: Decision problems verifiable in polynomial time by a deterministic Turing machine (or solvable in polynomial time by a non-deterministic machine).
  • NP-Hard: A problem X such that every problem in NP is polynomial-time reducible to X (Y ≤p X, ∀ Y ∈ NP). X does not need to be in NP.
  • NP-Complete: A problem that is both in NP and NP-Hard. (Proved by reducing a known NPC problem to it).
Cook's Reduction Chain (Syllabus Core)

Circuit-SAT ≤p SAT ≤p 3-SAT ≤p Clique ≤p Vertex Cover ≤p Hamiltonian Cycle ≤p TSP

5. Asymptotic Shortcuts & Growth Ladder

Standard Growth Order (Slowest → Fastest)

1 < log log n < log n < √n < n < n log n < n² < n³ < 2n < n! < nn

Limit Test (Fastest Way to Compare f & g)

Compute L = limn→∞ f(n) / g(n) (apply L'Hôpital if ∞/∞):

  • L = 0 ⇒ f(n) = o(g(n)) & O(g(n))
  • 0 < L < ∞ ⇒ f(n) = Θ(g(n))
  • L = ∞ ⇒ f(n) = ω(g(n)) & Ω(g(n))

Loop Pattern → Complexity

  • i += c (linear step) ⇒ Θ(n)
  • i *= c or i /= c ⇒ Θ(logc n)
  • i = i² or i = √i ⇒ Θ(log log n)
  • Nested j = 1..i (triangular) ⇒ Θ(n²)

Common Non-Master Recurrences

  • T(n) = T(n−1) + 1 ⇒ Θ(n)
  • T(n) = T(n−1) + n ⇒ Θ(n²)
  • T(n) = 2T(n−1) + 1 ⇒ Θ(2n)
  • T(n) = T(√n) + 1 ⇒ Θ(log log n)

6. Simple Step-by-Step Playbooks (How to Solve Exam Questions)

Use the module pills or search box at the top to filter these step-by-step recipes.

AVL Tree Insert & Rotations M1

  1. Insert key as in a normal BST.
  2. Walk back up to root, updating BF = h(L) − h(R).
  3. Stop at the first unbalanced node (|BF| > 1).
  4. Check the two steps toward the inserted key: LL → Right rotate; RR → Left rotate; LR → Left(child) then Right(node); RL → Right(child) then Left(node).

Solving Recurrences (Iteration) M1

  1. Expand T(n) 3 times to expose the k-th step pattern.
  2. Set base condition: n / bk = 1 (k = logb n) or n − k = 1 (k = n − 1).
  3. Substitute k and sum the resulting arithmetic or geometric series.

BFS & DFS Graph Traversals M2

  1. BFS (Queue): Enqueue start & mark visited immediately; pop, visit unvisited neighbors in alphabetical/numerical order. Gives shortest unweighted path.
  2. DFS (Stack / Recursion): Record d[u] on entry, f[u] when all neighbors finish.
  3. Edge types (DFS): Back edge (to ancestor) = cycle; Forward (to descendant); Cross (to finished subtree).

Topological Sort (Kahn's & DFS) M2

  1. Kahn's (BFS): Compute in-degree of all vertices → enqueue all with 0 → pop u, append to order, decrement neighbors' in-degree (enqueue if 0).
  2. DFS Method: Run DFS and list vertices in decreasing order of finish time f[u].
  3. Only valid for a DAG (if Kahn's outputs < V nodes, a cycle exists).

Kosaraju's SCC (3 Steps) M2

  1. Run DFS on G; push each vertex onto a stack when it finishes.
  2. Reverse all edge directions to build transpose graph GT.
  3. Pop vertices from stack and run DFS on GT — each DFS tree is one Strongly Connected Component.

Union-Find (Rank + Path Compression) M2

  1. Find(x): Follow parent pointers to root, then point every node on the path directly to the root.
  2. Union(x, y): Find roots rx, ry. Attach smaller-rank root under larger-rank root.
  3. Increment rank by 1 only when both roots have equal rank.

Strassen's Matrix Multiplication M2

  1. Partition A, B into four n/2 × n/2 submatrices.
  2. Compute 7 products P₁…P₇ (instead of 8) using additions/subtractions.
  3. Combine P₁…P₇ to form C₁₁, C₁₂, C₂₁, C₂₂ ⇒ T(n) = 7T(n/2) + Θ(n²) = Θ(n2.807).

Fractional Knapsack (Greedy) M3

  1. Compute profit-to-weight ratio pi / wi for every item.
  2. Sort items in descending order of pi / wi.
  3. Greedily take whole items while wi ≤ Wrem; for the first item that doesn't fit, take fraction Wrem / wi.

Kruskal's vs Prim's MST M3

  1. Kruskal's: Sort all edges ascending → pick cheapest edge that doesn't create a cycle (Union-Find) until V − 1 edges. Best for sparse graphs.
  2. Prim's: Start at given root → maintain min-edge cost to tree for each outside vertex → repeatedly add cheapest crossing edge and update neighbors. Best for dense graphs.

Dijkstra's Shortest Path M3

  1. Set dist[src] = 0, all others ∞.
  2. Pick unvisited vertex u with minimum dist[u] and lock it.
  3. Relax every neighbor v: if dist[u] + w(u,v) < dist[v], update dist[v].
  4. Trap: Never use on graphs with negative edge weights.

0/1 Knapsack (DP Table + Trace) M3

  1. Build (n+1) × (W+1) table; row 0 and col 0 = 0.
  2. For each cell (i, w): if w < wt[i] copy K[i−1, w]; else take max(K[i−1, w], val[i] + K[i−1, w − wt[i]]).
  3. Trace items: Start at (n, W). If K[i, w] ≠ K[i−1, w], item i is chosen and move to (i−1, w − wt[i]); else move to (i−1, w).

Matrix Chain Multiplication M3

  1. Extract dimensions p₀, p₁, …, pₙ where matrix Aᵢ is pi−1 × pi.
  2. Set main diagonal m[i, i] = 0.
  3. Fill upper triangle by chain length L = 2..n: test every split i ≤ k < j, store min cost in m[i, j] and best k in s[i, j].
  4. Parenthesize recursively at s[1, n].

Floyd–Warshall All-Pairs M3

  1. Initialize D⁰ with edge weights (0 on diagonal, ∞ if no edge).
  2. For each intermediate vertex k = 1..V: copy row k, col k, and diagonal unchanged.
  3. Update every other cell: D[i,j] = min(D[i,j], D[i,k] + D[k,j]).
  4. Negative diagonal entry D[i,i] < 0 ⇒ negative cycle.

N-Queens (Backtracking) M3

  1. Place 1 queen per row r = 1..n.
  2. Column c is safe iff no previous queen shares column c, main diagonal (r − c), or anti-diagonal (r + c).
  3. If no column is safe in row r, backtrack to row r − 1 and try the next column.

TSP via LC Branch & Bound M4

  1. Reduce root matrix: Subtract each row min, then each col min; sum of all subtracted values = root lower bound C.
  2. Branch i → j: Set row i, col j, and M[j, start] to ∞; re-reduce matrix for Δ.
  3. Child cost: C(child) = C(parent) + M[i,j] + Δ.
  4. Always expand the live node with the lowest cost; prune any node with C ≥ best_tour.

NP-Completeness Proof Template M4

  1. Step 1 (X ∈ NP): State the certificate (witness) and show it can be verified in polynomial time.
  2. Step 2 (X is NP-Hard): Pick a known NPC problem Y (e.g. 3-SAT or Clique).
  3. Step 3 (Reduction Y ≤p X): Give a poly-time construction f(y) and prove y ∈ Y ⇔ f(y) ∈ X (both directions!).

Bin Packing Approximations M4

  1. First Fit (FF): Put item in the first bin with enough room (≤ 1.7·OPT).
  2. Best Fit (BF): Put item in the bin that leaves the least leftover space (≤ 1.7·OPT).
  3. First Fit Decreasing (FFD): Sort items descending first, then run FF (≤ (11/9)·OPT + 6/9).

Top 4 KTU PCCST502 Exam Traps
  • Direction of Reduction: To prove X is NP-Hard, reduce a known NPC problem Y to X (Y ≤p X), never X ≤p Y.
  • 0/1 vs Fractional Knapsack: Greedy by p/w fails for 0/1 Knapsack — always use DP for 0/1.
  • Dijkstra vs Floyd–Warshall: Dijkstra fails on negative edges; Floyd–Warshall handles negative edges as long as there are no negative cycles.
  • Randomized Quicksort: Expected time is Θ(n log n) regardless of input order, but worst-case is still Θ(n²) (Las Vegas: always correct, runtime varies).
