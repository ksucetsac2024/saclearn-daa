The greedy method and fractional knapsack

A greedy algorithm builds its answer one piece at a time, always taking whatever looks best right now and never undoing a choice. It is fast and simple, but it only gives the optimum for problems with the right structure.

Words you need

  • Objective function: the quantity to maximise or minimise (total profit, total cost).
  • Feasible solution: any answer that satisfies the constraints (fits in the knapsack, forms a tree…).
  • Optimal solution: a feasible solution with the best objective value.

Control abstraction

Algorithm Greedy(a, n)       // a[1..n] holds the n inputs
{
    solution := ∅;
    for i := 1 to n do
    {
        x := Select(a);                     // pick the best remaining input
        if Feasible(solution ∪ {x}) then
            solution := Union(solution, x);
    }
    return solution;
}

Select chooses by a greedy criterion and removes the input from a. Feasible checks that adding it keeps the solution valid. Union adds it. Every greedy algorithm in this module (knapsack, Kruskal, Prim, Dijkstra) fills in these three functions differently.

Fractional knapsack

You have a knapsack of capacity M and n objects. Object i has weight wᵢ and profit pᵢ. You may take any fraction xᵢ of an object (think gold dust, not gold bars) and earn pᵢxᵢ.

maximise Σ pᵢ xᵢ subject to Σ wᵢ xᵢ ≤ M, 0 ≤ xᵢ ≤ 1, 1 ≤ i ≤ n

Greedy criterion: take objects in decreasing order of profit per unit weight pᵢ/wᵢ. Take each one whole while it fits; take a fraction of the first one that does not fit; stop.

Algorithm GreedyKnapsack(M, n)
// p[1..n], w[1..n] already sorted so that p[i]/w[i] ≥ p[i+1]/w[i+1]
{
    for i := 1 to n do x[i] := 0.0;
    U := M;                                     // remaining capacity
    for i := 1 to n do
    {
        if (w[i] > U) then break;
        x[i] := 1.0;  U := U − w[i];
    }
    if (i ≤ n) then x[i] := U / w[i];
}

Time: sorting by ratio is O(n log n) and the loop is O(n), so O(n log n) overall (O(n) if the input is already sorted).

Worked example

n = 5, M = 16, profits (24, 30, 18, 10, 14), weights (6, 15, 3, 10, 4).

Object12345
pᵢ / wᵢ42613.5

Order by ratio: 3, 1, 5, 2, 4. Take object 3 (weight 3, profit 18, room left 13), object 1 (6, 24, room 7), object 5 (4, 14, room 3). Object 2 weighs 15, so take 3/15 = 0.2 of it for profit 6. Room left 0.

x = (1, 0.2, 1, 0, 1), total profit = 18 + 24 + 14 + 6 = 62. Compare other greedy rules: largest profit first gives 34; smallest weight first gives 59. Only the ratio rule is always optimal.

Why the ratio rule is optimal (exchange argument)

Take any optimal solution that differs from the greedy one. Somewhere it uses less of a high-ratio object i and more of a lower-ratio object j. Swap a small weight δ of j for the same weight of i: the total weight is unchanged and the profit changes by δ(pᵢ/wᵢ − pⱼ/wⱼ) ≥ 0. Repeating such swaps turns the optimal solution into the greedy one without ever losing profit, so greedy is optimal too.

Minimum cost spanning trees: Kruskal and Prim

Connect every town with roads using the least total road length. That is a minimum spanning tree (MST), and two greedy algorithms find one.

Definitions

For a connected, undirected, weighted graph G = (V, E), a spanning tree is a subset of edges that connects all vertices with no cycle. It always has exactly V − 1 edges. A minimum spanning tree has the smallest total weight among all spanning trees. If all weights are distinct, the MST is unique.

Why greedy works here: the cut property

Split the vertices into any two groups. The lightest edge crossing between the groups is safe: it belongs to some MST. Both algorithms keep adding such a "lightest crossing edge"; they differ only in which cut they look at.

Kruskal's algorithm

Look at edges from lightest to heaviest. Accept an edge if it joins two different trees; reject it if both ends are already in the same tree (it would make a cycle). Disjoint sets answer "same tree?" quickly.

MST-KRUSKAL(G, w):
    A = ∅
    for each vertex v: MAKE-SET(v)
    sort the edges of E into non-decreasing order of weight
    for each edge (u, v) in that order:
        if FIND-SET(u) ≠ FIND-SET(v):
            A = A ∪ {(u, v)}
            UNION(u, v)
    return A

Time: sorting O(E log E). Then 2E finds and V − 1 unions cost O(E α(V)). Since E ≤ V², log E ≤ 2 log V, so the total is O(E log E) = O(E log V). Sorting dominates.

Prim's algorithm

Grow one tree from a start vertex r. At each step add the cheapest edge from the tree to a vertex not yet in it. Each outside vertex v keeps key[v] = the weight of its cheapest edge into the tree so far.

MST-PRIM(G, w, r):
    for each u: key[u] = ∞; π[u] = NIL
    key[r] = 0
    Q = min-priority queue of all vertices, keyed by key[]
    while Q not empty:
        u = EXTRACT-MIN(Q)                // u joins the tree via edge (π[u], u)
        for each v in Adj[u]:
            if v ∈ Q and w(u, v) < key[v]:
                π[v] = u; key[v] = w(u, v)   // DECREASE-KEY

Time with a binary min-heap: V EXTRACT-MINs at O(log V) each, and up to E DECREASE-KEYs at O(log V) each: O((V + E) log V) = O(E log V). With a plain array instead of a heap (scan for the minimum): O(V²). With a Fibonacci heap: O(E + V log V).

Dijkstra's single-source shortest paths

Find the cheapest route from one source vertex to every other vertex, when no edge has a negative weight. It looks like Prim's algorithm, but the key of a vertex is its total distance from the source instead of one edge weight.

Relaxation

Every vertex v keeps an estimate d[v] of its distance from the source s (start: d[s] = 0, all others ∞) and a predecessor π[v]. Relaxing edge (u, v) asks: "is going through u a shortcut to v?"

RELAX(u, v, w):
    if d[u] + w(u, v) < d[v]:
        d[v] = d[u] + w(u, v)
        π[v] = u

The algorithm

DIJKSTRA(G, w, s):
    for each v: d[v] = ∞; π[v] = NIL
    d[s] = 0
    S = ∅                               // vertices whose distance is final
    Q = min-priority queue of all vertices, keyed by d[]
    while Q not empty:
        u = EXTRACT-MIN(Q)              // greedy choice
        S = S ∪ {u}
        for each v in Adj[u]:
            RELAX(u, v, w)              // DECREASE-KEY if d[v] drops
Why the greedy choice is safe

When u has the smallest d among unfinished vertices, any other route to u would have to leave the finished set S through some unfinished vertex y with d[y] ≥ d[u], and then continue along edges of weight ≥ 0. Such a route can never come back cheaper than d[u]. So d[u] is final the moment u is extracted. This argument breaks as soon as an edge can be negative.

Dynamic programming

When a recursive solution keeps solving the same subproblems again and again, solve each one once and store the answer in a table. That is dynamic programming (DP).

When DP applies

Optimal substructure

An optimal solution is built from optimal solutions to its subproblems.

Overlapping subproblems

The same smaller problems come up again and again. (In divide and conquer, like merge sort, they do not.)

Seeing the overlap: binomial coefficients

C(n, k) = C(n−1, k−1) + C(n−1, k), with C(n, 0) = C(n, n) = 1. Plain recursion recomputes the same values many times:

The plain recursion makes 2·C(n, k) − 1 calls, which is exponential: for C(30, 15) that is over 300 million calls, yet there are only 30 × 15 different subproblems. DP fills Pascal's triangle row by row instead, each entry once: O(nk) time.

Control abstraction (the four steps)

  1. Characterise the structure of an optimal solution: what are the subproblems?
  2. Recursively define the value of an optimal solution in terms of smaller subproblems (the recurrence).
  3. Compute the values bottom-up, smallest subproblems first, storing them in a table.
  4. Construct an optimal solution from the stored information (keep a second table of the choices made).

Step 3 can also be done top-down with memoisation: write the plain recursion, but check a table before computing and store each result after. Same complexity, easier to write.

Principle of optimality

Bellman's principle of optimality

An optimal sequence of decisions has the property that, whatever the initial state and first decision are, the remaining decisions must form an optimal sequence with respect to the state that results from the first decision.

In plain words: every piece of an optimal solution is itself optimal for its own subproblem. DP is only correct when this holds.

Holds: shortest paths

If the shortest route P → R → T passes through R, then its P → R part must be a shortest P → R route. If a shorter P → R route existed, swapping it in would make the whole route shorter: a contradiction ("cut and paste").

Fails: longest simple paths

Triangle with vertices a, b, c, all edges weight 1. The longest simple path from a to c is a → b → c (length 2). Its piece a → b has length 1, but the longest simple path from a to b is a → c → b (length 2). The subpaths are not optimal, because the two halves compete for the same vertices.

Matrix chain multiplication

Multiplying matrices is associative, so (AB)C = A(BC), but the two orders can cost wildly different amounts of work. DP finds the cheapest bracketing.

The problem

Multiplying a p×q matrix by a q×r matrix takes p·q·r scalar multiplications. A chain A₁A₂…Aₙ where Aᵢ has dimensions pi−1 × pᵢ is described by the list ⟨p₀, p₁, …, pₙ⟩.

Why the order matters

A (10×100), B (100×5), C (5×50). (AB)C costs 10·100·5 + 10·5·50 = 5,000 + 2,500 = 7,500. A(BC) costs 100·5·50 + 10·100·50 = 25,000 + 50,000 = 75,000. Ten times more work for the same answer.

Trying every bracketing is hopeless: the number of bracketings is the Catalan number, which grows like 4ⁿ/n^1.5.

DP formulation

Let m[i, j] = the minimum cost of computing Aᵢ…Aⱼ. The last multiplication splits the chain at some k: (Aᵢ…Aₖ)(Aₖ₊₁…Aⱼ). The left part is pi−1×pₖ and the right part is pₖ×pⱼ, so the final multiplication costs pi−1·pₖ·pⱼ.

Recurrence
m[i, i] = 0 m[i, j] = min over i ≤ k < j of { m[i, k] + m[k+1, j] + pi−1·pₖ·pⱼ } s[i, j] = the k that gave the minimum

Fill the table by chain length: first all chains of length 2 (the diagonal just above the main one), then length 3, and so on up to m[1, n]. Each entry only needs shorter chains, which are already done.

MATRIX-CHAIN-ORDER(p):           // p = ⟨p0, …, pn⟩
    for i = 1 to n: m[i, i] = 0
    for L = 2 to n:                    // chain length
        for i = 1 to n − L + 1:
            j = i + L − 1;  m[i, j] = ∞
            for k = i to j − 1:
                q = m[i, k] + m[k+1, j] + p[i−1]·p[k]·p[j]
                if q < m[i, j]: m[i, j] = q; s[i, j] = k

PRINT-OPTIMAL-PARENS(s, i, j):
    if i == j: print "A" i
    else: print "("; PRINT-OPTIMAL-PARENS(s, i, s[i, j])
          PRINT-OPTIMAL-PARENS(s, s[i, j] + 1, j); print ")"

Analysis: three nested loops of at most n each: Θ(n³) time; two n×n tables: Θ(n²) space.

Floyd–Warshall: all-pairs shortest paths

Distances between every pair of vertices at once, by allowing more and more vertices to be used as stopovers. It is a dynamic program that works even with negative edges.

The idea

Number the vertices 1…n. Let Dᵏ[i][j] be the shortest distance from i to j using only vertices from {1, …, k} as intermediate stops. D⁰ is just the edge-weight matrix (0 on the diagonal, ∞ where there is no edge). At step k, the best i → j route either avoids k (the old value) or goes i → k → j:

Recurrence
Dᵏ[i][j] = min( Dᵏ⁻¹[i][j], Dᵏ⁻¹[i][k] + Dᵏ⁻¹[k][j] )
FLOYD-WARSHALL(W):              // W = n×n weight matrix
    D = W
    for k = 1 to n:
        for i = 1 to n:
            for j = 1 to n:
                if D[i][k] + D[k][j] < D[i][j]:
                    D[i][j] = D[i][k] + D[k][j]
                    P[i][j] = P[k][j]        // predecessor, to rebuild paths
    return D

Analysis: three nested loops: Θ(n³) time, Θ(n²) space (one matrix can be updated in place, because row k and column k do not change during step k).

Doing it by hand quickly

In Dᵏ, row k and column k are copied unchanged, and so is the diagonal. For every other cell, compare the old value with (row-k entry in its column) + (column-k entry in its row). If row k or column k has ∞ in that position, the cell cannot change.

Negative edges and negative cycles

Negative edge weights are fine. A negative-weight cycle is not: going around it again and again makes the path cheaper without limit, so "shortest path" has no meaning for vertices that can reach the cycle. Floyd–Warshall then gives meaningless numbers, but it does reveal the problem: some vertex ends with D[i][i] < 0 (a route from i back to itself with negative total). Check the diagonal of the final matrix.

Backtracking and the N-Queens problem

Build a solution one component at a time. The moment a partial solution cannot possibly be completed, abandon it and go back to try the next option. This prunes huge parts of the search.

Vocabulary

  • The solution is a tuple (x₁, x₂, …, xₙ), chosen one component at a time.
  • Explicit constraints restrict each xᵢ to a set of values on its own. N-Queens: xᵢ ∈ {1, …, n}, the column of the queen in row i.
  • Implicit constraints relate components to each other. N-Queens: no two queens share a column (xᵢ ≠ xⱼ) or a diagonal (|xᵢ − xⱼ| ≠ |i − j|).
  • The state space tree has one level per component; each path from the root is a partial tuple.
  • A bounding function tests a node: if the partial tuple already breaks a constraint, the node is killed and its whole subtree is skipped.
  • Node states: live (generated, children not all generated), E-node (being expanded now), dead (fully explored or killed).

Control abstraction

Algorithm Backtrack(k)
// x[1..k−1] has been chosen; try every value for x[k]
{
    for (each x[k] ∈ T(x[1], …, x[k−1])) do
    {
        if (B_k(x[1], x[2], …, x[k]) ≠ false) then    // bounding function
        {
            if (x[1], …, x[k]) is a path to an answer node
                then write (x[1:k]);
            if (k < n) then Backtrack(k + 1);
        }
    }
}

T(…) gives the candidate values for the next component; Bk is the bounding function. Backtracking is a depth-first search of the state space tree that skips killed subtrees.

N-Queens

Place n queens on an n×n board so that no two attack each other (same row, column or diagonal). One queen per row is automatic, so x[k] is the column of the queen in row k.

Algorithm Place(k, i)
// true if a queen can go in row k, column i
{
    for j := 1 to k − 1 do
        if ((x[j] = i)                          // same column
            or (Abs(x[j] − i) = Abs(j − k)))     // same diagonal
        then return false;
    return true;
}

Algorithm NQueens(k, n)
{
    for i := 1 to n do
    {
        if Place(k, i) then
        {
            x[k] := i;
            if (k = n) then write (x[1:n]);
            else NQueens(k + 1, n);
        }
    }
}

Call NQueens(1, n). Place is O(k), and the worst case explores an exponential number of nodes, but bounding kills most of them early. Solutions: 4 queens has 2, 5 has 10, 8 has 92.
